# RapidJAM Configurator v0.9.1

## Highlights

**More reliable communication with current RapidJAM firmware.** This release works around known firmware bugs, so you do not need to update the firmware.

- Live Hall readings no longer fail after the controller is powered on. Previously they could keep failing until a calibration was run.
- Occasional corrupted responses from the controller are retried for live readings, and requests are now sent one at a time.
- Hall calibration is less affected by the previously read button: the first reading after switching buttons is discarded, and the idle values are measured one button at a time.
- Saving is safer. Saved settings are read back and compared, and the Hall calibration table is only written after two identical reads, so a corrupted response is not written back to the controller.

These workarounds are harmless on firmware that already has the fixes and can be removed later. See [fw-workarounds.md](../fw-workarounds.md).

## Notes

- Not yet verified on a physical device. Please report any save failure or slow calibration.

The build is not code-signed. Windows SmartScreen may show a warning on first launch. See [DISTRIBUTION.md](../../DISTRIBUTION.md) for verification steps and the WebView2 requirement.

# RapidJAM Configurator v0.9.1（日本語）

## 主な変更

**現行の RapidJAM ファームウェアとの通信が安定しました。** ファームウェア側の既知の不具合を Configurator 側で回避するため、ファームウェアを更新する必要はありません。

- 電源を入れた直後でも、Hall のリアルタイム表示が失敗しにくくなりました。これまでは、キャリブレーションを一度行うまで失敗し続けることがありました。
- コントローラーからの応答が壊れることがある問題に対し、リアルタイム表示では再試行します。通信は 1 リクエストずつ送るようになりました。
- Hall のキャリブレーションで、直前に読んだボタンの値が混ざりにくくなりました。ボタンを切り替えた直後の 1 回は読み捨て、待機時の値はボタンごとにまとめて測定します。
- 保存がより安全になりました。保存した内容は読み戻して比較します。Hall の校正テーブルは、2 回の読み取りが一致した場合にだけ書き込むため、壊れた応答がコントローラーへ書き戻されません。

これらの回避策は、修正済みのファームウェアでも問題なく動作し、あとから取り除けます。詳細は [fw-workarounds.md](../fw-workarounds.md) を参照してください。

## 注意

- 実機では未検証です。保存の失敗やキャリブレーションの遅さに気づいた場合は、ご報告ください。

このビルドにはコード署名がありません。初回起動時に Windows SmartScreen の警告が出ることがあります。検証手順と WebView2 の要件は [DISTRIBUTION.md](../../DISTRIBUTION.md) を参照してください。
